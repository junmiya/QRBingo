# QRBingo Constitution

## Core Principles

### I. 公平性はサーバーが担保する (Server-Authoritative Fairness)
順位・当選に関わる判定(抽選、マーキング、ビンゴ判定、順位確定)は必ずサーバー側で行う。
端末の申告時刻・クライアント計算の結果を順位決定に使ってはならない。
順位の基準は常に「何球目で条件を満たしたか(ball index)」であり、通信遅延・配信遅延・端末性能が順位に影響してはならない。

### II. 個人情報を持たない (PII-Free by Default)
メールアドレス・氏名等の個人情報をアプリのデータストアに保存しない。
当選者との連絡は「当選コード」の照合により、主催者が自前のチャネルで行う。
ニックネームは公開情報として扱い、NGワードフィルタと主催者による非表示手段を必ず提供する。

### III. カードは決定論的に生成する (Deterministic Cards)
ビンゴカードはカードID(シード)から決定論的に再現できなければならない。
グリッド全体を正とするのではなく、シードを正とする。これにより検証・監査・重複判定が
軽量に実装でき、v1(サーバーレス版)との互換性が保たれる。

### IV. v1 サーバーレスモードの維持 (Offline Mode Preserved)
既存の静的・サーバーレス版(読み上げ+手動マーク)は「オフライン/小規模モード」として
削除せず維持する。v2 の変更が v1 の動作を壊してはならない。共通ロジック(カード生成・
ライン判定)は v1/v2 で単一ソース(`js/common.js` 系)を共有する。

### V. 検証ファースト (Verify Before Ship)
機能追加はブラウザ実機(Playwright)での E2E 確認を経てからコミットする。
順位決定・同着処理・重複カード排除など公平性に関わるロジックには自動テストを必須とする。

## 制約 (Constraints)

- UI 言語は日本語。モバイルファースト。
- フロントエンドは静的ホスティング可能な構成を維持する(ビルド必須の SPA 化はしない)。
- バックエンドは Firebase(Firestore / Cloud Functions / Anonymous Auth / App Check)。
- 依存ライブラリはベンダリングし、実行時 CDN 依存を作らない。

## Governance

- 本憲章はすべての実装判断に優先する。逸脱が必要な場合は spec に理由を明記し承認を得る。
- 仕様変更は `specs/` 配下の該当 spec を先に更新してから実装する(Spec-Driven)。
